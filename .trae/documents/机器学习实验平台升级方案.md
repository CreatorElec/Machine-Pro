# 机器学习实验平台升级方案

## Context（为什么做）

课程大作业评分标准中，当前项目在几项关键指标上存在明显短板（详见对话中的差距分析）：
- **自己实现的模型比例 = 0%**：12 个模型全部来自 sklearn，`svm.py`/`data_random.py` 只是半成品脚手架。
- **无法比较多种算法**：`pipeline.py` 一次只训练一个模型，而课程目标明确是"展示和比较各种算法在经典数据集上的性能"。
- **无 tricks/调参/改进**：没有标准化、交叉验证、网格搜索，也没有 ROC/学习曲线等分析可视化。
- **技术栈与课程推荐不符**：课程推荐 Vue + WebSocket，项目为原生 JS + REST。
- **算法覆盖窄**：只有分类/回归，缺少课程要求的聚类、降维。

本轮目标（用户已确认，**暂不需要报告/架构文档**）：补齐上述短板，让项目从"单模型演示"升级为"可自研算法、可批量对比、可调参、可视化丰富、Vue+WebSocket 前后端"的完整实验平台。

环境约束：`node`/`npm`/`git` 未安装 → 前端**不使用构建工具**，采用 Vue 3 global 构建（本地 vendor，含 CDN 回退）。Python 3.12 / sklearn 1.8 / numpy 2.4 / scipy 1.17。

---

## 一、后端改造

### 1.1 `backend/algorithms.py` → `backend/algorithms/` 包

现有 `main.py`/`pipeline.py` 以 `from algorithms import ...` 扁平导入（启动时 cwd=`backend/`），因此新包的 `__init__.py` **必须重新导出同名符号**，保证零回归。删除原 `algorithms.py` 及 `backend/__pycache__/algorithms.cpython-313.pyc`。

```
backend/algorithms/
├── __init__.py            # 再导出: AlgorithmDef, ParamDef, coerce_params,
│                          #   get_algorithm, CLASSIFICATION_ALGORITHMS, REGRESSION_ALGORITHMS,
│                          #   UNSUPERVISED_ALGORITHMS, get_unsupervised_algorithm, algorithms_meta()
├── base.py                # ParamDef / AlgorithmDef(新增 source 字段) / coerce_params / register 助手
├── sklearn_models.py      # 现 12 个 sklearn 算法定义（原样迁移）
├── unsupervised_models.py # KMeans / PCA / DBSCAN / 层次聚类（sklearn）+ 自研 MyKMeans / MyPCA
└── custom/
    ├── __init__.py        # import 子模块以触发注册
    ├── linear.py          # MyKNN(分类+回归)、MyLogisticRegression(GD)、MyLinearRegression、MyRidge、MyLinearSVM(hinge)
    ├── tree.py            # MyDecisionTree (CART，gini/entropy，分类+回归)
    └── probabilistic.py   # MyGaussianNB
```

`AlgorithmDef` 增加 `source: str = "sklearn"`（取值 `sklearn` / `custom`）并在 `to_dict()` 输出，前端据此显示来源切换。

### 1.2 自研算法（纯 numpy，sklearn 兼容接口）

统一实现 `fit / predict`，分类器追加 `predict_proba`；暴露 `classes_`、`coef_`/`feature_importances_` 以便复用现有 `_feature_importance()` 与 ROC。关键差异点：
- `fit` 中 **`classes_ = np.unique(y)`（用全量 y，而非 y_train）**，`predict_proba` 列顺序与 `classes_` 对齐，避免训练集缺类导致 ROC 列错位。
- `coef_` 二分类 `(n_features,)`、多分类 `(n_classes, n_features)`；`feature_importances_` 必须一维、长度 = 特征数。
- `max_depth` 等 select 参数接受 `None`（前端"无限制"经 `coerce_params` 转 `None`）。
- GD 类算法（逻辑回归/SVM）支持可选 `progress_cb(iter, loss)`，供 WebSocket 推送逐轮 loss。

自研算法注册为 `source="custom"`，与对应 sklearn 算法**同名配对**（如 `knn`、`logistic_regression`、`decision_tree`、`naive_bayes`、`linear_regression`、`ridge`、`kmeans`、`pca`），前端可在两者间切换并对比。

### 1.3 训练/评估流水线（`backend/pipeline.py`）

- 新增 `standardize` 步骤：`StandardScaler` **仅对特征**且在**训练集上 fit**（避免泄漏）；CV/调参用 `make_pipeline(StandardScaler(), est)` 使每折自洽。
- 聚类/降维单独流程（无目标列）：scaler 在**全量 X** 上 fit，返回 `silhouette`/`inertia`/`explained_variance_ratio` 等。
- 复用现有 `preprocess()` 的填充与 one-hot 逻辑；把目标处理部分拆分，使无监督路径可复用特征清洗。

### 1.4 新增后端模块

| 文件 | 职责 |
|------|------|
| `backend/tuning.py` | K 折交叉验证（分类用 `StratifiedKFold`，返回 mean±std）；网格搜索 `GridSearchCV` → best_params + best_score |
| `backend/compare.py` | 批量对比：同一数据集跑 N 个算法，汇总指标 + 排名 + 关键指标（按任务取 accuracy 或 r2） |
| `backend/viz.py` | ROC（多分类 OvR + AUC）、学习曲线、决策边界（仅 2 特征，或先用 PCA 降到 2 维）、PCA 2D 散点 |
| `backend/unsupervised.py` | 聚类/降维编排：fit、评估、PCA 散点、KMeans 肘部数据 |

### 1.5 接口（`backend/main.py`、`backend/schemas.py`）

`schemas.py` 扩展：`TrainRequest` 增加 `source`、`standardize`、`cv_folds`；新增 `CompareRequest`、`TuneRequest`、`UnsupervisedRequest`（`target: Optional[str]`）。

REST（新增，均在 `app.mount("/")` **之前**注册）：
- `POST /api/compare` — 多算法批量对比
- `POST /api/tune` — 网格搜索调参
- `POST /api/unsupervised` — 聚类/降维
- `POST /api/viz/roc`、`/api/viz/learning-curve`、`/api/viz/boundary`、`/api/viz/pca-scatter` — 按需懒加载图表数据

WebSocket（**必须在 `app.mount("/", StaticFiles...)` 之前注册**，否则被 catch-all 吞掉）：
- `/ws/train` — 客户端发送训练配置，服务端流式推送：
  `{type:start,total}` → `{type:progress,index,algorithm,source}` → `{type:loss,algorithm,iter,loss}`（自研 GD 模型） → `{type:result,algorithm,result}` → `{type:done,comparison}` / `{type:error,message}`
- WS 处理函数为 async，阻塞的 sklearn 调用用 `await run_in_threadpool(...)` 包裹，避免阻塞事件循环。

## 二、前端重构（Vue 3 + WebSocket，无构建工具）

```
frontend/
├── index.html              # 挂载点；<script src="./vendor/vue.global.prod.js" onerror="CDN回退">
│                           #  + ./vendor/echarts.min.js + <script type="module" src="./js/app.js">
├── vendor/vue.global.prod.js   # 本地 vendor（离线可用）
├── vendor/echarts.min.js       # 图表库
├── js/app.js               # Vue createApp 根 + 组件（配置面板/结果面板/对比视图/聚类视图）
├── js/api.js               # REST + WebSocket 客户端封装
├── js/charts.js            # ECharts 封装（ROC、对比柱状图、学习曲线、散点、决策边界热力图）
└── style.css               # 复用并扩展
```

要点：
- 用 **ES 原生模块**（`<script type="module">` + `import`）拆分 js，无需打包器；Vue/ECharts 通过 vendor 的 global 脚本暴露为 `window.Vue`/`window.echarts`。
- 新增"算法来源"切换（sklearn / 自研），沿用后端 `params` 元数据驱动的动态参数表单逻辑（迁移现有 `renderParamForm`）。
- 新增"多算法对比"面板（多选算法 → 经 WebSocket 流式训练 → 对比表 + 柱状图 + 排名）。
- 新增"聚类/降维"面板（KMeans 聚类散点 + silhouette/inertia，PCA 方差解释率 + 2D 投影）。
- 结果面板增加图表：ROC 曲线、学习曲线、决策边界、预测对比（保留现有混淆矩阵/分类报告/特征重要性）。

## 三、实施顺序

1. **后端骨架重构**：建 `algorithms/` 包，迁移 12 个定义，删旧文件；跑通现有 REST，确认无回归。
2. **自研算法**：`custom/linear.py`、`custom/tree.py`、`custom/probabilistic.py` + `unsupervised_models.py` 中的 `MyKMeans`/`MyPCA`，注册 `source="custom"`。
3. **schema + pipeline**：加 `standardize` / `cv_folds` / `source`；标准化与无监督分支。
4. **tuning.py / compare.py / viz.py / unsupervised.py**。
5. **main.py**：新增 REST 路由 + `/ws/train` WS（顺序在 mount 之前）。
6. **前端 Vue 重构**：vendor 下载 → `js/api.js`、`js/charts.js`、`js/app.js`、`index.html`、`style.css`。
7. **联调与验证**（见下）。

## 四、验证方式

- **启动**：`backend/` 下 `python -m uvicorn main:app --reload`。
- **REST 冒烟**：`/api/health`、`/api/algorithms`（断言含 `source`）；`POST /api/train`（sklearn 与自研各一次，`standardize=true`）；`POST /api/compare`、`/api/unsupervised`、`/api/viz/roc`。
- **WS 冒烟**：用 python `websockets` 客户端（`uvicorn[standard]` 已含）连接 `/ws/train`，断言握手成功且收到 `progress`/`result`/`done`（证明路由顺序正确）。
- **浏览器端到端**：启动服务后用浏览器子代理打开 `http://127.0.0.1:8000/`，检查 Vue 加载、WS 帧、触发训练、确认 ROC / 学习曲线 / 决策边界 / 聚类散点正常渲染；确认 `frontend/vendor/vue.global.prod.js` 存在（离线可用）。
- **回归**：确认原有单模型训练的指标、混淆矩阵、分类报告、特征重要性输出不变。

## 五、风险与回退

- vendor 下载失败（离线）→ `index.html` 保留 CDN `src` 回退；若运行时确定离线，则用纯 SVG 简易图表降级。
- 自研算法性能不如 sklearn 属正常，前端并列展示即可（对比本身即为评分点）。
- `data_random.py` / `svm.py` 为课程练习脚手架，**本轮不动**（`svm.py` 中的决策边界绘图能力已由 `viz.py` 覆盖）。
